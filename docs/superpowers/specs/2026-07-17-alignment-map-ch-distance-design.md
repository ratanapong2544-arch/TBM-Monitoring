## การตัดสินใจของ user (2026-07-17)

1. **"ค่าพิกัด" = chainage** (ไม่ใช่ lat/lng หรือ UTM)
2. **ป้าย CH ยึดระบบ KMZ** — เหตุผล: ตรงกับ CH หัวเจาะ (callout `CH 7+863`), ตรงกับตำแหน่งจริงบนแผนที่,
   และตรงกับ `profileGeo.js` ที่ใช้ชุดเดียวกันอยู่แล้ว → ไม่ต้องแก้ data เดิม
3. **ป้ายระยะทางยึดเลขทางการ** — เป็นเอกสารสัญญาที่เจ้าของงานคาดหวัง และเป็นตัวที่ใช้คิด % ความคืบหน้า
   ⚠️ **ผลที่ยอมรับแล้ว:** ช่วง IS2→IS1 ป้ายระยะ (1,715.097) จะลบกับผลต่าง CH บนภาพ (1,670.902) ไม่ได้
   user รับทราบและเลือกทางนี้เอง — **ห้ามมีใครมา "แก้ให้ตรงกัน" ทีหลังโดยไม่ถาม**
4. **CH วางเป็นบรรทัดในป้ายอาคารเดิม** ไม่ใช่กล่องแยกตาม mockup — เพราะระบบกันป้ายทับปรับจูนมาหลายรอบ

## สิ่งที่จะเปลี่ยน

### `src/utils/alignmentGeo.js` (pure data — jest-safe, ห้าม import three/maplibre)

- `SHAFTS[].ch` — ขยายความละเอียดจากทศนิยม 1 ตำแหน่งเป็นค่าเต็ม (8830.5→8830.488 ฯลฯ)
  ปลอดภัย: `ch` ปัจจุบัน**ไม่มีใครอ่าน** (`AlignmentMapView` ใช้แค่ name/fullName/role/capacity/lng/lat/labelDir)
- เพิ่ม `SHAFT_SPANS` — ระยะทางทางการ 3 ช่วง + คอมเมนต์บันทึกส่วนต่าง 44.195 ม. และเหตุผล

### `src/utils/alignmentGeo.test.js` (ใหม่)

ล็อกตัวเลขไม่ให้ถูกแก้โดยบังเอิญ:
- ผลรวม `SHAFT_SPANS` = `TOTAL_ROUTE_DISTANCE` (8,874.683)
- `SHAFTS.ch` ตรงกับ `CH_EXCAV_START − ระยะสะสม` และเรียงลดหลั่นถูกต้อง
- ส่วนต่าง KMZ↔ทางการ = 44.195 อยู่ที่ช่วง IS2→IS1 ช่วงเดียว (regression guard ของสมมติฐานทั้ง spec)

### `src/components/views/AlignmentMapView.jsx`

1. `fmtCH(ch, dp = 0)` — รับจำนวนทศนิยม default 0 → callout หัวเจาะ + popup instrument ไม่เปลี่ยน
2. ป้ายอาคาร: เพิ่ม `<span class="ch">CH x+xxx.xxx</span>` ท้าย `.lab` · ซ่อนเมื่อ `.mini` และบนมือถือ
3. ป้ายระยะทาง: marker ที่กึ่งกลางช่วง (`lngLatAtCh((chA+chB)/2)`) — ตัวหนังสือขาวมีเงา ไม่มีกล่อง
   - **มุมหมุน** = `atan2` ของ `map.project()` 2 จุดบนแนว → ได้มุมบนจอจริงรวมผล pitch+bearing ให้เอง
   - พลิก 180° เมื่อจะกลับหัว (คุมมุมไว้ใน −90..90)
   - หมุนที่ `<span class="lab">` ลูก **ห้ามหมุน marker root** (maplibre เขียน inline transform ทับ)
4. Collision: ป้ายระยะเข้า `shaftMarkersRef` ด้วย priority ต่ำสุด + ธง `noMini` (ไม่มีรูปแบบย่อ → ซ่อนเลย)
   - หมุน**ก่อน**วัด `getBoundingClientRect` เสมอ ไม่งั้นกรอบผิด
   - ใช้ class `.lab` กับตัวที่หมุน → โค้ด collision เดิมวัดถูกโดยไม่ต้องแก้ selector

   ⚠️ **ข้อ 4 นี้ใช้ไม่ได้จริง — ดู "สิ่งที่เปลี่ยนหลัง verify" ข้างล่าง**

## สิ่งที่เปลี่ยนหลัง verify บนเบราว์เซอร์จริง (2026-07-17, commit `c62b15c`)

ดีไซน์ข้อ 4 พังตอนเจอของจริง เพราะ 3 เรื่องที่คิดในหัวไม่มีทางเจอ:

**(ก) กรอบแนวแกนวัดป้ายที่หมุนไม่ได้** — ข้อความ 79×20px พอหมุน 62° กรอบแนวแกนกลายเป็น 55×79px
(ใหญ่แต่ข้างในโล่ง) → ระบบตัดสินว่า "ทับ" ทั้งที่ตัวหนังสือยังไม่แตะกัน แล้วซ่อนป้ายทิ้งฟรี ๆ
→ **ป้ายระยะแยกเป็นคนละเฟส** วัดด้วย 4 มุมจริง + SAT · **ระบบกันป้ายทับเดิมไม่ถูกแตะเลยแม้แต่บรรทัดเดียว**
(ดีกว่าไปยัด `noMini` เข้าไปในของที่จูนมาหลายรอบ)

**(ข) กึ่งกลางช่วงไม่ว่างจริง 2 ใน 3 ช่วง** ที่มุม "ดูทั้งแนว" — ป้ายอาคาร (230×83) + กล่องหัวเจาะ
กินพื้นที่เกือบหมด · วัดแล้วมีที่ว่าง แค่ไม่ใช่ตรงกลางเป๊ะ (3,065 ต้องไถ 45px · 1,715 ต้องไถ 15px)
→ `placeDistLabels()` ไล่ลอง `DIST_TRIES` (ไถตามแนว ±90px × ออกข้าง ±20px เรียงจากขยับน้อยสุด)
คำนวณล้วนไม่แตะ DOM ต่อ candidate · สะสมป้ายที่วางแล้วเป็นสิ่งกีดขวางกันป้ายระยะทับกันเองตอนซูมออก
· ไม่มีที่ว่างจริง ๆ ค่อยซ่อน

**(ค) บรรทัด CH ทำป้าย IS4 สูงขึ้น 16px** (67→83) จนเลข CH ไปนั่งใต้แถวปุ่ม `.a3m-ctrl`
ซึ่งเป็น overlay ที่**ไม่ได้อยู่ในระบบกันทับ** → `fitRoute` padding ล่าง 74→96
(ค่านี้ผูกกับความสูงป้าย IS4 — เพิ่ม/ลดบรรทัดเมื่อไรต้องวัดใหม่)

**บทเรียน:** ตัวเลขเถียงชนะการอ่านภาพ — ผมดูภาพแล้วสรุปว่า "ตัวหนังสือไม่ได้แตะกัน ระบบวัดผิด"
แต่ SAT บอกว่าทับจริง · และ probe ที่ลืมปลด `.hidden` ก่อนวัด (ได้ 0×0 → SAT ตอบ "ทับ" เสมอ)
เกือบทำให้สรุปผิดว่า "ไม่มีที่ว่าง ทำไม่ได้" — **ตรวจเครื่องมือวัดก่อนเชื่อผลวัด**
