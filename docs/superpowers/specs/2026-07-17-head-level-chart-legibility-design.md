### 1.1 ข้อค้นพบ: ข้อมูลหัวเจาะบน prod ผูกเลขริงผิด

**หลักฐาน:**

| ตรวจ | ผล |

**สรุป: `Ring_Typical` มีเลขริงที่ใช้ได้อยู่แล้ว (เพี้ยนคงที่ −1) แต่ import รอบเก่าโยนทิ้ง** — ต้นเหตุทั้งหมด

> เคยเชื่อว่า drift เป็น +1/+2 สลับกัน — ตรวจแล้วพบว่า "+2" คือ false match จาก V-triple ที่ชนกับริงข้างเคียง (สลับไปมา 44 ครั้ง = ไม่ใช่รูปแบบจริง) **+1 คือสัญญาณจริง**

### 1.4 VRT = `[36] Articulation vertical angle` — ไม่ใช่ค่าการหมุน

หา VRT เจอโดย **brute-force ทั้ง 533 คอลัมน์** (รอบแรกหาไม่เจอเพราะเดาว่าชื่อต้องมีคำว่า Rolling → เทียบแค่ 8 คอลัมน์ = เดา ไม่ใช่ค้น)

| คอลัมน์ | ตรง VRT (d=1) | mean \|Δ\| |
|---|---|---|
| **`[36] Articulation vertical angle`** | **107/150** | **0.051°** |
| `[783] V Angle (Art)` | 55/150 | 0.056° |
| `[501]/[503]/[788] Rolling *` | ≤5/150 | ~0.27° |

ที่ไม่ตรง 43 ริง คลาดกัน p50 = 0.02° = คนละจังหวะอ่านค่าในริงเดียวกัน ไม่ใช่คนละปริมาณ
(sanity: วิธีเดียวกันหา `[765] V Deviation (Head)` เจอเองเป็นอันดับ 1 ที่ 117/150 → เครื่องมือวัดเชื่อถือได้)

**VRT คือมุมงอข้อต่อ articulation แนวดิ่ง = การบังคับเลี้ยวขึ้น/ลง** ไม่ใช่ roll:

- `corr(VRT, ค่าเบี่ยง Head)` = **−0.862** — ยิ่งต่ำกว่าแนว ยิ่งงอขึ้น = proportional steering
- ช่วงดึงกลับ P400–440 VRT เฉลี่ย **0.398°** vs ช่วงวิ่งนิ่ง P600–660 **0.016°** = **ต่าง 25 เท่า**
- ไฟล์**มีคอลัมน์ Rolling จริง 5 ตัว แต่ไม่มีตัวไหนตรง VRT** → ถ้า VRT เป็น roll ต้องมีสักตัวตรง
- corr กับความชัน (−0.13) และกับก้ม/เงย (−0.02) ≈ 0 → เกาะ**ความผิดพลาดของตำแหน่ง** ไม่ใช่ท่าทาง
- ชื่อย่อลงล็อก: ไฟล์มีคู่ `[36] Articulation **vertical** angle` / `[37] Articulation **horizontal** angle` → **VRT = VeRTical**

**ผลตามมา 2 ข้อ:**
1. ป้ายกราฟ VRT ปัจจุบัน `ค่าการหมุน/เอียงหัวเจาะ` (HeadLevelView.jsx:182) **ผิด** → ต้องแก้
2. `headPosture.js:29` `rollDeg = vrt × ROLL_GAIN(20)` **ผิด** — เอามุมบังคับเลี้ยวไปหมุนรอบแกนกระบอก → **ตัด roll ออก** (ผู้ใช้เคาะ 2026-07-17)

### 2.2 ทางแก้: โฟกัสล่าสุด + แถบภาพรวม

**กราฟหลัก (โฟกัส)**
- ค่าเริ่มต้น = **150 ริงล่าสุด** · ปุ่มเลือก `50 / 150 / ทั้งหมด`
- **แกน Y ล็อกสมมาตร ขั้นละ 25 อย่างน้อย ±100** → แถบ ±75 อยู่ตำแหน่งเดิมบนจอเสมอ (เทียบข้ามช่วงได้ + จำตำแหน่งได้) ขยายเป็น ±150/±200… เฉพาะเมื่อข้อมูลในหน้าต่างไม่พอดี
- ครึ่งล่างที่ว่างคือ**สัญญาณ ไม่ใช่ที่เสีย** — บอกว่าเครื่องวิ่งค่อนไปทางสูง
- **ช่วงที่เกินเกณฑ์ = พื้นหลังแดงจาง (ReferenceArea) แทนจุดแดงรายริง**
- แกน X เป็น**ตัวเลข** (`type="number"`) · tooltip เพิ่มวันที่
- 3 เส้นคงเดิม (Head เข้ม 2.6px / Art / Tail) — ในหน้าต่างโฟกัสแยกกันออก (pitch ล่าสุด −43…+53mm)

**แถบภาพรวม (context) — แบบ B "แถบสถานะ"**
- แถบสีต่อริงทั้ง 635 ริง: **เขียว = ในเกณฑ์ · เหลือง = ใกล้ขอบ (>0.66×tol) · แดง = เกิน ±75** เข้มตามความลึก
- กรอบ "ช่วงที่ดูอยู่" เลื่อน/ลากได้ → คุมหน้าต่างของกราฟหลัก
- สูง ~48px · legend ในตัว

**การ์ด KPI "เกิน ±75"**
- เปลี่ยนเป็น**สถานะริงล่าสุด**: "อยู่ในเกณฑ์" / "เกินเกณฑ์"
- subtext = ประวัติ: "เคยหลุด 2 ช่วง · 184 ริง"
- ตอบ *"ตอนนี้เป็นไง"* ไม่ใช่ *"เคยเป็นไง"*

**Bullseye "เป้า 2 แกน"**
- ยังโชว์ริงล่าสุดจริง (P699) แต่ H ไม่มี → **จุดตกบนแกนตั้ง + ป้ายกำกับว่า "ไม่มีข้อมูลแนวราบ (มีถึง P509)"**
- ห้ามปล่อยให้ดูเหมือน H = 0 จริง

**VRT — คงเป็นการ์ดแยกด้านล่างเหมือนเดิม** (ผู้ใช้เลือก 2026-07-17)
- **แก้ป้ายให้ตรงความหมาย**: `VRT (°) ต่อริง` → คงชื่อ VRT ไว้ (ทีมเรียกแบบนี้) แต่ subtitle เปลี่ยนจาก `ค่าการหมุน/เอียงหัวเจาะ` → **"มุมงอข้อต่อ articulation แนวดิ่ง — ค่าบวก = บังคับหัวขึ้น · ยิ่งมาก = ยิ่งดัดกลับแรง"**
- **แกน Y ล็อก ±0.6** (ข้อมูลจริง −0.21…+0.51) เลขกลม
- เกณฑ์สีแดงเดิมที่ `|vrt| ≥ 0.3` **คงไว้** — ข้อมูลจริง p90 = 0.4 → แดง = กำลังดัดกลับแรงผิดปกติ ซึ่งตรงความหมายใหม่พอดี
- ครอบ P3–P699 ครบแล้ว (ไม่เริ่มที่ P321 อย่างที่เคยคิด)
