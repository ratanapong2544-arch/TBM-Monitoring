# ระดับหัวเจาะ — กราฟอ่านรู้เรื่อง + ข้อมูลชุดใหม่ (2026-07-17)

## ที่มา

ผู้ใช้: *"ปรับกราฟหน้านี้ใหม่ให้มันดูรู้เรื่องกว่านี้ พร้อมอัพเดทข้อมูลใหม่"* + ไฟล์ `TBM1_Ring321-699.csv`

หน้า `HeadLevelView` (แท็บ "ระดับหัวเจาะ") กราฟ "แนวโน้มค่าเบี่ยง Head/Art/Tail" อ่านไม่ออก — และระหว่างตรวจข้อมูลพบว่า**ข้อมูลบน prod ผูกกับเลขริงผิด**

## ส่วนที่ 1 — ข้อมูล (สำคัญกว่ากราฟ)

### 1.1 ข้อค้นพบ: ข้อมูลหัวเจาะบน prod ผูกเลขริงผิด

`bulkUpdateSegmentHead` รอบ 2026-07-07 นำเข้า 370 ริงจาก `Ring_Typical_M7-R00510.csv` โดย**ทิ้งเลขริงของ guidance แล้ว match ด้วย chainage** (สมมติ `finishCH ≈ Chainage(Head) + 1.2m`) → ค่าไปตกผิดริง drift ผันแปร +1…+13

**หลักฐาน:**

| ตรวจ | ผล |
|---|---|
| CSV ใหม่ ring→date เทียบ app ring→date (แก้ TZ เป็นเวลาไทย) ไล่ drift −15…+15 | ยอดแหลมชัดที่ **drift 0 = ตรงเป๊ะ 335/372** (mean \|Δ\| 0.14 วัน) · drift ±1 → ~270 · **drift +11 → 0** |
| ค่าในชีทปัจจุบัน P400 = −468/−428/−357 | ตรงเป๊ะทั้ง 3 ค่ากับ **CSV ริง 406** (CSV บอก P400 ต้องเป็น −347/−293/−207) |
| chainage offset จริง (คำนวณจาก 142 คู่ที่ยืนยันแล้ว) | median −11.0m แต่ **p25 −15.2 / p75 −1.4 = ไม่คงที่** → chainage ไม่เคยเป็นกุญแจที่ใช้ได้ |

**สรุป: `Ring_Typical` มีเลขริงที่ใช้ได้อยู่แล้ว (เพี้ยนคงที่ −1) แต่ import รอบเก่าโยนทิ้ง** — ต้นเหตุทั้งหมด

### 1.2 กุญแจที่ถูกต้อง: `app ring N ↔ guidance Segment Ring (N−1)`

ทดสอบบนช่วงซ้อน P321–P509 (150 ริง):

| d | exact triple | ≤2mm ทั้ง 3 ค่า | mean \|Δ\| |
|---|---|---|---|
| 0 | 7 | 12 | 11.22 mm |
| **1** | **111** | **124** | **2.63 mm** |
| 2 | 31 | 35 | 8.40 mm |
| 3 | 3 | 3 | 16.65 mm |

**d=1 ใช้ได้ทั้งช่วง ไม่ใช่การเดา** — app P numbering **ต่อเนื่อง P1→P716 ไม่มีช่องว่างเลย** และริง temp อยู่คนละ namespace (`T7…T1` ↔ guidance `−7…−1`) → ไม่มีการแทรก/ข้ามริง ดังนั้น d เปลี่ยนระหว่าง P2–P321 ไม่ได้ทางตรรกะ

> เคยเชื่อว่า drift เป็น +1/+2 สลับกัน — ตรวจแล้วพบว่า "+2" คือ false match จาก V-triple ที่ชนกับริงข้างเคียง (สลับไปมา 44 ครั้ง = ไม่ใช่รูปแบบจริง) **+1 คือสัญญาณจริง**

## ส่วนที่ 2 — กราฟ

### 2.1 ปัญหา (วัดจากข้อมูลจริง)

| # | ปัญหา | ตัวเลข |
|---|---|---|
| 1 | **สเกลถูก excursion ยึด** | ข้อมูลกาง −587…+79 = 666mm → แถบ ±75 เหลือ 22% ของสูง · 200 ริงล่าสุด (−40…+79) ถูกอัดเป็นเส้นเดียว |
| 2 | แกน Y เลขไม่กลม | 139 / −41 / −241 / −441 / −641 |
| 3 | จุดแดงเป็นก้อน | breach 167 ริงติดกัน = มวลแดงทึบ บอกอะไรไม่ได้ |
| 4 | แกน X เป็น category | ระยะบนจอ ≠ ระยะจริง · ไม่มีวันที่ |
| 5 | การ์ด "เกิน ±75" นับสะสม | 184 ริง ทั้งที่เป็น excursion เก่าที่แก้จบแล้ว → อ่านเหมือนเครื่องกำลังหลุด |

**เรื่องจริงของข้อมูล:** excursion 2 ครั้ง — P33–P61 (29 ริง ลึกสุด 104mm) และ P325–P491 (167 ริง ลึกสุด **587mm**) — แล้ว **P500–P699 (200 ริงล่าสุด) −40…+79mm เกินแค่ริงเดียว (P574 = 79mm)** = เครื่องคุมอยู่

### 2.2 ทางแก้: โฟกัสล่าสุด + แถบภาพรวม

**กราฟหลัก (โฟกัส)**
- ค่าเริ่มต้น = **150 ริงล่าสุด** · ปุ่มเลือก `50 / 150 / ทั้งหมด`
- **แกน Y ล็อกสมมาตร ขั้นละ 25 อย่างน้อย ±100** → แถบ ±75 อยู่ตำแหน่งเดิมบนจอเสมอ (เทียบข้ามช่วงได้ + จำตำแหน่งได้) ขยายเป็น ±150/±200… เฉพาะเมื่อข้อมูลในหน้าต่างไม่พอดี
- ครึ่งล่างที่ว่างคือ**สัญญาณ ไม่ใช่ที่เสีย** — บอกว่าเครื่องวิ่งค่อนไปทางสูง
- **ช่วงที่เกินเกณฑ์ = พื้นหลังแดงจาง (ReferenceArea) แทนจุดแดงรายริง**
- แกน X เป็น**ตัวเลข** (`type="number"`) · tooltip เพิ่มวันที่
- 3 เส้นคงเดิม (Head เข้ม 2.6px / Art / Tail) — ในหน้าต่างโฟกัสแยกกันออก (pitch ล่าสุด −43…+53mm)

**แถบภาพรวม (context) — แบบ B "แถบสถานะ"**
- แถบสีต่อริงทั้ง 635 ริง: **เขียว = ในเกณฑ์ · เหลือง = ใกล้ขอบ (>0.66×tol) · แดง = เกิน ±75** เข้มตามความลึก
- กรอบ "ช่วงที่ดูอยู่" เลื่อน/ลากได้ → คุมหน้าต่างของกราฟหลัก
- สูง ~48px · legend ในตัว

**การ์ด KPI "เกิน ±75"**
- เปลี่ยนเป็น**สถานะริงล่าสุด**: "อยู่ในเกณฑ์" / "เกินเกณฑ์"
- subtext = ประวัติ: "เคยหลุด 2 ช่วง · 184 ริง"
- ตอบ *"ตอนนี้เป็นไง"* ไม่ใช่ *"เคยเป็นไง"*

**Bullseye "เป้า 2 แกน"**
- ยังโชว์ริงล่าสุดจริง (P699) แต่ H ไม่มี → **จุดตกบนแกนตั้ง + ป้ายกำกับว่า "ไม่มีข้อมูลแนวราบ (มีถึง P509)"**
- ห้ามปล่อยให้ดูเหมือน H = 0 จริง

**VRT**
- คงกราฟแท่งเดิม แต่**แกน Y ล็อก ±0.6** (ข้อมูลจริง −0.2…+0.51) เลขกลม
- มีเฉพาะ P321–P699 → กราฟจะเริ่มที่ P321 (ไม่ใช่บั๊ก)
